# Changelog

## 2.0.0 — Agentic Design Harness

First public release.

- Self-contained: the eleven first-party design workflows are bundled and authenticated by a local
  lock (`scripts/gen-lock.py`). Workflow instructions resolve helpers, workspaces and execution modes
  through `docs/harness-package.json`; nothing is fetched from or run in another repository.
- No plugin is supplied; plugin-registration receipts are rejected and plugin-only hosts use
  folder-execution. Contextual AI-tell review and direct use of original references remain intact.
- Stripped local owner/group identity from tar archives and checked archive comments/metadata;
  publication text/archive privacy regressions and gates.
- Persistent project brief, surface/state contract, brand/system context, components and separated
  decisions, taste, lessons and debt; supporting material loads only when needed.
- New projects receive independent working copies; brand/product discovery happens there rather
  than contaminating the reusable source. Existing apps can integrate additively.
- Existing READMEs, development instructions, rules and skills are preserved. Namespaced design
  instructions, conflict candidates and a local installation report support deliberate integration.
- Static host checks follow actual explicit routes and file-relative imports; design context budgets
  measure the installed design module. Tests cover absent/commented/example imports and coexistence.
- Public docs, CI definition, versioned downloads, archive parity, licence and checksums.

Local fixture/install/browser suites are executed release checks. Native Claude/Cowork activation,
hidden account state and new model-led creative acceptance are not certified by those checks.
The accepted creative baseline is unchanged; visual work still needs rendered review and iteration.
